# Install and run a table app (Windows and Linux)

One small Node service, the **hub**, runs the whole installation on the table's PC:

```
 phone ──(scans QR)──► http://<table PC>:8080/phone/     phone pages, served by the hub
 table screen (Chrome kiosk) ──► http://localhost:8080/table/     the table app
 objects/pucks ──TUIO/UDP 3333──► hub ──WebSocket /tuio──► table app
 table + phone ──/proxy/<source>/*──► hub ──HTTPS (+ key)──► data APIs   (keys never leave the hub; optional)
```

Everything runs from one folder with **only Node.js 20.11 or newer**: no npm install, no Python, no internet needed once installed.
The app's name and id come from `app.json` in this folder; below, `<id>` is that id (for example `interactive-table`).

## 1. Requirements

| | Windows 10/11 | Linux (Ubuntu/Debian/Fedora, systemd) |
|---|---|---|
| Node.js 20.11+ | `winget install OpenJS.NodeJS.LTS` (install for all users) | your package manager or https://nodejs.org |
| Browser | Chrome, Chromium or Edge (Edge is built in) | Chrome or Chromium |
| Network | the PC and the visitors' phones on the same Wi-Fi/LAN (see section 3) | same |

## 2. Quick start

Unzip `<id>-<version>.zip` somewhere permanent (for example `C:\Tables\<id>` or `/opt/<id>`).

**Windows**
```bat
scripts\windows\start-all.cmd
```
**Linux**
```bash
scripts/linux/start-hub.sh &      # the hub
scripts/linux/start-kiosk.sh      # the table screen (inside the desktop session)
```
The hub prints what it serves, for example:
```
table      http://localhost:8080/table/
phone      http://192.168.1.20:8080/phone/?src=table   (QR code points here; source: lan)
TUIO       udp 3333 -> ws /tuio
```
A QR code is always visible at the bottom-left of the table ("Scan to play"); scan it with a phone on the same Wi-Fi. Tapping it, or the QR button at the bottom right, shows a larger version.

Add `--tuio` to `start-kiosk` when the real object-tracking hardware is connected. Without it, the on-screen dock of pucks is used (drag a puck out to place it, drag its knob or use the mouse wheel to turn it, drag it back to lift it).

## 3. How the QR code works

The QR code is generated by the hub and refreshed every minute. It encodes one URL:

| Situation | Setting | QR carries |
|---|---|---|
| **Default (LAN)**: phones join the venue Wi-Fi | nothing | `http://<best LAN address of this PC>:8080/phone/?src=table` |
| The PC has several adapters and the wrong one is chosen | `advertiseHost` = the IP or name phones should use | `http://<that host>:8080/phone/?src=table` |
| Phone pages hosted publicly (works on mobile data) | `phoneUrl` = `https://example.org/my-table/` | that URL plus `?src=table` |

For public hosting, copy the `phone/` folder to any static web host. (Proxied data is then unavailable to it, because keys stay on the hub.)

The hub picks the LAN address by preferring private ranges (192.168.x, 10.x, 172.16-31.x) on real Wi-Fi/Ethernet adapters over virtual ones (WSL, Hyper-V, VirtualBox, Docker, VPN). It logs the alternatives at startup; override with `advertiseHost` if it guessed wrong. If the hub listens only on `127.0.0.1`, the table says phone pages are unavailable instead of showing a code that cannot work.

**If the phone cannot open the page after scanning** (the usual causes, in order):
1. The phone is on mobile data or a different Wi-Fi than the PC.
2. **Client isolation** ("AP isolation") is on for that Wi-Fi: phones may not talk to other devices. Turn it off for the venue network, or use public hosting.
3. **Windows Firewall**: the install script opens TCP 8080 for Private/Domain networks. If Windows classifies the Wi-Fi as *Public*, set it to Private (Settings, Network) or reinstall with `-IncludePublicProfile`.
4. Linux firewall (`ufw`/`firewalld`): allow TCP 8080.

## 4. Data sources and API keys (optional)

If the app reads live data, each source is declared under `proxies` in `hub.config.json` (see `config/hub.config.example.json`): its base URL, how the key is sent, and the **only** endpoints pages may ask for (regular expressions, each with a cache time). Pages call `/proxy/<source>/<endpoint>`; anything not on the list is refused.

Put each key in `config/keys/<source>.txt` (on its own line; `#` lines are ignored; UTF-8 or UTF-16 both work) or the environment variable `HUB_KEY_<SOURCE>` (`weather-api` becomes `HUB_KEY_WEATHER_API`). Keys are read only by the hub, kept off every web page, and **never accepted from `hub.config.json`** (the hub refuses to start if it finds one there). The installers restrict the key files to administrators/the service account.

Every good response is cached on disk (`data/cache`). Without a key or internet, pages get the last good copy (up to 14 days) with the header `x-hub-cache: stale` and its date in `x-hub-data-at`, so the app can label it honestly ("Saved, 3 May") instead of "Live".

## 5. Settings

Defaults are fine for most sites. Optional file: `hub.config.json` next to the `hub` folder or in `config\` (copy `config/hub.config.example.json`). Precedence: defaults < file < environment < command line.

| Setting | Env | Flag | Default |
|---|---|---|---|
| `port` | `HUB_PORT` | `--port` | 8080 |
| `host` (bind address) | `HUB_HOST` | `--host` | 0.0.0.0 (all interfaces; `127.0.0.1` = this PC only, no phones) |
| `phoneUrl` | `HUB_PHONE_URL` | `--phone-url` | derived from the LAN address |
| `advertiseHost` | `HUB_ADVERTISE_HOST` | `--advertise-host` | auto |
| `qrNote` (line under the QR) | `HUB_QR_NOTE` | | "Use the same Wi-Fi as the table" |
| `idleSeconds` (start over after this long with nobody at the table; 0 = never) | `HUB_IDLE_SECONDS` | `--idle-seconds` | 90 |
| `udp.port` (TUIO) | `TUIO_UDP_PORT` | `--udp-port` | 3333 |
| `dataDir` | `HUB_DATA_DIR` | `--data-dir` | `<install>/data` |
| `offline` (proxies serve their cache only) | `HUB_OFFLINE=1` | `--offline` | false |
| `proxies` | | | none (section 4) |
| `ui` (free-form settings passed to the pages in `/api/config`; no secrets) | | | `{}` |

Check the effective settings with `node hub/hub.mjs --print-config`.

## 6. Run at boot (the real installation)

**Windows** (PowerShell as Administrator, in the unpacked folder):
```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\windows\install-service.ps1 -KioskUser Exhibit -Tuio -DisableSleep
```
Creates the start-at-boot task `<id>-hub` (runs as SYSTEM, restarts on failure), the start-at-logon task `<id>-kiosk` for the kiosk browser, and the firewall rule. Set the PC to **auto-login** as the kiosk user. Remove with `uninstall-service.ps1`.

**Linux**:
```bash
sudo scripts/linux/install-service.sh --tuio
```
Creates the systemd unit `<id>-hub` and a desktop autostart entry for the kiosk (enable desktop auto-login). Logs: `journalctl -u <id>-hub` and `data/logs/hub.log`. Remove with `uninstall-service.sh`.

Because every name comes from the app id, two different table apps can be installed on one PC (give them different ports).

## 7. Idle reset and attract mode

After `idleSeconds` (default 90) with no touch, key, or object placed, lifted or deliberately moved, the table starts over: every puck lifted, each scene's `reset` run, the background reset. The last 15 seconds are counted down on screen ("Starting over in 12 s, touch to keep going"); any activity cancels it. It then shows an invitation until someone touches the table or places an object. The QR code stays visible throughout.

An object resting on the table with ordinary sensor noise does **not** keep the table awake (it must travel about 16 px or turn 3 degrees); after a reset it is ignored until it is lifted and placed again. For testing, `?idle=10` in the URL overrides the setting.

## 8. Check it works

```bash
node scripts/smoke.mjs        # starts a throwaway hub and checks the table, phone page, QR decode, proxy and path safety
```
Open `http://<PC address>:8080/health` for the live status (TUIO packets, proxy caches). Open `http://localhost:8080/table/input-debug.html?source=tuio` to see raw touches and objects while calibrating (see HARDWARE.md in the source repository).

## 9. Security notes

- The hub serves only the table, the phone pages, the QR code, the read-only proxies you configured (allow-listed endpoints only), and the TUIO WebSocket. There are no admin or write endpoints.
- It listens on all interfaces by default so phones can reach it. On a shared network use `host: "127.0.0.1"` (table only) or put it on its own VLAN.
- The proxies never forward the visitor's headers, never follow redirects (a redirect could leak a key), cap concurrent upstream calls, and by default reject non-JSON upstream bodies.
- Plain HTTP is used inside the venue network; the phone pages need no camera, microphone or location.
